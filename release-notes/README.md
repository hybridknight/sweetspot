# Release notes

Before tagging a release, add `<version>.md` here (for example, `1.0.3.md`).
The release workflow publishes this text to GitHub and the app’s update page.

Keep it to 2–3 short user benefits and at most 100 words. Describe what users
can do or what gets better. Include an installation tip only when needed.
Use plain paragraphs. Leave out contributor names, avatars, commit hashes,
build details, test results, and internal implementation details.

Review these notes with the release changes before creating the version tag.
Do not publish a version’s notes until its changes are included in that release.
