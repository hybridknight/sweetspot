## App identity

The app name is **Sweet Spot**, also described as **Sweet Spot for YouTube Music**. Its codename, executable, and package name are `sweetspot`. Shared links use `ssytm://`.

| Integration | Identifier |
| --- | --- |
| Desktop app | `ooo.bkk.sweetspot` |
| Browser userscript namespace | `sweetspot` |

Sweet Spot uses its own app identity and data profile. When moving from an earlier installation, sign in and reconnect integrations in Sweet Spot; the earlier profile remains separate. Development uses an isolated `sweetspot-dev` profile.

## First launch

1. Install or unpack the build for your OS.
2. [Sign in to YouTube Music](/docs/sign-in) in the separate browser window. Sweet Spot brings your session back automatically, with in-app sign-in available as a fallback.
3. Open **Settings → Appearance → Player skins** to choose a look and open the dedicated player.
4. Try **Player → Equalizer**, **Player → General**, and **Player → Lyrics** to set up your sound.
5. Enable the local API only if you need a custom client.

## Signing in

Sweet Spot first uses your default browser when it is Chrome, Edge, Brave, Chromium, Vivaldi, or Helium and a supported installation is available. Otherwise it chooses another installed supported browser. Safari, Firefox, and Zen are not supported by this browser sign-in method.

The sign-in window uses a fresh, temporary profile. Your usual browser profile stays separate, so saved passwords and existing sign-ins may not be available. Complete any verification Google requests, then Sweet Spot verifies and transfers the YouTube Music session, closes the window, and removes its temporary profile.

If browser sign-in is unavailable or fails, Sweet Spot automatically continues with in-app sign-in. You can also choose **Use in-app sign-in** while waiting. If a passkey gets stuck there, choose Google's **Try another way**. **Cancel** or closing the progress window stops the attempt. A browser attempt times out after five minutes; the in-app flow allows ten minutes and offers retry if it fails.

Google may reject a sign-in method or end a session later. Sign in again when needed. Sandboxed or nonstandard browser installations may use the in-app fallback.

See [Sign in to YouTube Music](/docs/sign-in) for the full walkthrough, progress messages, and troubleshooting.

## If macOS blocks Sweet Spot

Current Mac releases aren’t notarized by Apple. On first launch, including after an update, macOS may say **“Sweet Spot” Not Opened** and that Apple could not verify it is free of malware.

For a download you trust from [Sweet Spot’s website](https://sweetspot.bkk.ooo) or its [official GitHub releases](https://github.com/hybridknight/sweetspot/releases), follow these steps:

1. Try opening **Sweet Spot** from **Applications**. In that warning, click **Done**.
2. Open **System Settings → Privacy & Security**.
3. Scroll down to the Sweet Spot warning and click **Open Anyway**.
4. Authenticate if asked, then confirm **Open**.

This creates an exception for Sweet Spot, following [Apple’s instructions](https://support.apple.com/en-us/102445). Your settings are unaffected. These steps apply to the verification warning above; if macOS reports that the app **will damage your computer** or **is damaged**, stop and check the download instead.

## macOS credential protection

Sweet Spot uses macOS Keychain to protect the keys for stored credentials. This is a security feature that lets the app remember approved integrations without leaving their encryption keys readable in its profile. Disposable caches do not request keychain access.

If macOS shows a Keychain or Secret Storage dialog, approve it only when you recognize Sweet Spot and trust the installed build. The password belongs in the macOS system dialog; Sweet Spot does not receive it. Repeated prompts can indicate a locked keychain or a changed app signature. Read [Local data and privacy](/docs/internals/encrypted-stores#why-macos-may-ask-for-your-password) for details.

## Updates

Sweet Spot checks GitHub Releases for new versions. Keep the app updated for security and feature fixes.

On macOS, choose **Download DMG** in the update window or **Settings → About**. Sweet Spot detects Apple Silicon or Intel, including an Intel app running through Rosetta, and opens the matching download in your browser. If a direct download cannot be found, it opens the release page instead.

Open the downloaded DMG, quit Sweet Spot, then drag the new app into **Applications** and choose **Replace**. Your settings are kept. Automatic update checks notify you about new versions; installation uses these manual steps.

Launch Sweet Spot from **Applications**. If macOS blocks it, follow [the Open Anyway steps above](#if-macos-blocks-sweet-spot).

Older versions may still show **Install now** and fail signature validation. Download the matching DMG from the [website](https://sweetspot.bkk.ooo) and replace the app manually to upgrade from those versions.
